## 1. 範圍與目標

1. 帳號（Supabase Auth：Email+Password、Google OAuth）
2. Tenant 自動建立 + 單 Tenant 單使用者

4. Pillar Cluster 兩步規劃（AI）
5. 文章生成：大綱 → 訪談 → 草稿 → Tiptap 編輯器

- 第 6 節：Google Search Console 整合（OAuth、同步、maturity）

## 2. 技術棧

| 層 | 選擇 |
|---|---|
| Framework | Next.js 16 App Router + TypeScript |
| Hosting | Vercel（Fluid Compute，Node.js 24，timeout 300s）|
| Auth + DB + Storage | Supabase（自託管 Postgres + Auth + Storage）|
| DB access | Supabase JS / @supabase/ssr（走 PostgREST，RLS 自動生效）|
| Migrations | Supabase CLI（`supabase/migrations/*.sql`）|
| AI | Vercel AI Gateway + AI SDK v6（OIDC 認證）|
| 編輯器 | Tiptap + `tiptap-markdown` extension |
| 圖片 | Supabase Storage（bucket：`article-images`），signed upload URL 直傳 |
| i18n | next-intl（locale segment：`/[locale]/...`）|
| 樹狀拖拉 | dnd-kit |
| Ghost SDK | `@tryghost/admin-api` |
| Markdown ↔ HTML | `marked`（publish 時）、Tiptap storage（編輯時）|
| 加密 | Node.js AES-256-GCM，key 從 `ENCRYPTION_KEY` env var |

- Drizzle ORM — RLS 搭配 PostgREST 更自然，少一套工具
- Vercel Queues / Workflow — M1 不上背景任務
- Clerk — 改用 Supabase Auth（與 DB 同源）
- Vercel Blob — 改用 Supabase Storage

## 3. 架構

### 3.1 執行模型

```
Browser
  │
  │  (Next.js App Router)
  ▼
Next.js 16 on Vercel Fluid Compute
  │
  ├─ Server Components       → 讀資料（@supabase/ssr + anon key + cookie）
  ├─ Server Actions          → 短任務寫入 / 表單
  ├─ Route Handlers (/api/*) → AI streaming、Ghost publish、signed upload URL
  │
  ▼
Supabase Postgres + Auth + Storage    Vercel AI Gateway → Claude
                                      Ghost Admin API
```

### 3.2 認證與 Session

- Middleware 每個 request 呼叫 `@supabase/ssr` 的 `updateSession()` 刷新 cookie
- RSC 取 `createServerClient()` 讀使用者 JWT，RLS 自動套用
- Server Actions / Route Handlers 同一套
- 敏感操作（storage signed upload URL、加解密）使用 `SUPABASE_SERVICE_ROLE_KEY`，只在 server-only 模組

### 4.3 Postgres functions

#### normalize_url

```sql
CREATE OR REPLACE FUNCTION normalize_url(u text) RETURNS text
  LANGUAGE plpgsql IMMUTABLE AS $$
DECLARE
  result text;
BEGIN
  IF u IS NULL OR u = '' THEN RETURN NULL; END IF;
  result := lower(u);
  result := regexp_replace(result, '[#?].*$', '');   -- 剝 fragment 與 query string
  result := regexp_replace(result, '/+$', '');       -- 剝結尾的 /
  RETURN result;
END $$;
```

對應 `lib/url/normalize.ts` 提供相同邏輯的 JS 實作（避免 round-trip）。

### 4.4 Triggers

#### handle_new_user
註冊成功 → 建 tenant 與 owner membership：

```sql
CREATE FUNCTION handle_new_user() RETURNS trigger SECURITY DEFINER AS $$
DECLARE new_tid uuid;
BEGIN
  INSERT INTO tenants(name)
    VALUES (coalesce(NEW.raw_user_meta_data->>'name', NEW.email) || '''s workspace')
    RETURNING id INTO new_tid;
  INSERT INTO tenant_members(tenant_id, user_id, role)
    VALUES (new_tid, NEW.id, 'owner');
  RETURN NEW;
END $$ LANGUAGE plpgsql;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION handle_new_user();
```

## 5. RLS

### 5.1 Helper function

```sql
CREATE FUNCTION user_tenant_ids() RETURNS SETOF uuid
  LANGUAGE sql STABLE SECURITY DEFINER AS $$
    SELECT tenant_id FROM tenant_members WHERE user_id = auth.uid()
  $$;
```

### 5.2 通用 policy（除 `tenants` 外）

```sql
ALTER TABLE <table> ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON <table>
  FOR ALL TO authenticated
  USING (tenant_id IN (SELECT user_tenant_ids()))
  WITH CHECK (tenant_id IN (SELECT user_tenant_ids()));
```

### 5.3 `tenants` policy

```sql
CREATE POLICY own_tenants ON tenants
  FOR ALL TO authenticated
  USING (id IN (SELECT user_tenant_ids()))
  WITH CHECK (id IN (SELECT user_tenant_ids()));
```

### 5.4 Storage policy

Bucket `article-images`，path 規範為 `{tenant_id}/{article_id}/{kind}/{uuid}.{ext}`。

```sql
CREATE POLICY storage_tenant_isolation ON storage.objects
  FOR ALL TO authenticated
  USING (
    bucket_id = 'article-images'
    AND (storage.foldername(name))[1]::uuid IN (SELECT user_tenant_ids())
```

## 6. AI 生成流程

### 6.1 模型與端點對照

| 端點 | 模型 | 輸出 | 持久化 |

| `POST /api/ai/plan/step1` | `anthropic/claude-sonnet-4.6` | `streamText` | 否（暫態）|
| `POST /api/ai/plan/step2` | `anthropic/claude-sonnet-4.6` | `streamObject` | 使用者確認後一次寫入 |
| `POST /api/ai/outline` | `anthropic/claude-sonnet-4.6` | `streamObject` | `article_outlines` |

### 6.4 流程細節

#### Pillar Cluster（兩步）

**Step 1**：
- Input：`topic`（必填）、`audience_supplement`（選填）
- Output：`streamText` → 核心面向條列 + hub 策略概述
- UI：使用者可編輯輸出文字，或按「重新生成」
- 不持久化（使用者重整就重來）

**Step 2**：
- Input：Step 1 的「確認版本」文字
- Output：`streamObject` 符合 `pillarPlan`
- UI：樹狀介面逐步長出 pillar → articles
- 使用者按「儲存」→ 呼叫 Postgres function `create_pillar_plan(project_id, plan)` 原子寫入

#### 大綱生成

- Trigger：文章頁點「生成大綱」
- Input：article meta + pillar + brand_context
- Output：`streamObject` 符合 `outlineSchema`
- Persist：route handler 開頭 `status → outlining`；完成 `upsert article_outlines` + `status → outline_ready`

#### 訪談問題生成

- Trigger：大綱確認後按「開始訪談」
- Input：`outline.sections where needs_interview = true` + article meta + brand_context
- Output：`streamObject` 符合 `interviewSchema`（強制 ≤ 8 題）
- Persist：原子清空 `interview_questions`（for this article）→ 批次 insert；`status → interviewing`

**訪談 UI**：單頁清單（非 wizard）
- 每題顯示對應段落標題
- 每題有「跳過」按鈕
- 全域「全部跳過」
- 每題 onBlur debounced 500ms 自動存
- 所有題目 `status ≠ pending` 時可按「生成草稿」

#### 草稿生成

- Trigger：訪談完成或全跳過
- Input：完整 outline + interview Q&A（含 answer / status） + brand_context
- Prompt 規則：
  - sections 順序就是文章順序，標題沿用 outline.title
  - 有 answer 的段落：**必須基於 answer 撰寫，不得虛構**
  - `status=skipped` 的段落：以通用知識撰寫
  - 全文遵循 tone、preferred_terms，絕不使用 forbidden_terms
  - 輸出 Markdown（`##` 為 H2 段落）
- Output：`streamText`
- UI：中央顯示串流文字（非編輯器），完成後一鍵「進入編輯器」
- Persist：完成時 server 一次寫入
  - `body_markdown = <AI output>`
  - `body_tiptap = markdownToTiptap(body_markdown)`
  - `status = draft_ready`

#### 段落改寫（編輯器內）

- Trigger：Tiptap 選取文字 → floating menu 選動作
- 選項：更簡潔 / 更詳細 / 改語氣 / 自訂指令
- Input：selected text + instruction + brand_context
- Model：`anthropic/claude-haiku-4.5`
- UX：串流 inline 替換選取
- Persist：不直接寫 DB，編輯器 autosave 接手

#### Meta 建議

- Input：`article.title` + 截斷 body_markdown（4000 字）+ focus_keyword
- Model：Haiku
- Output：`streamObject` 符合 `metaSchema`
- UX：串流時兩個欄位同時更新（`streamObject` partial），使用者可採用或忽略

### 6.5 錯誤處理、取消、並發

| 情境 | 行為 |
|---|---|
| 使用者按取消 | `AbortController` → fetch 中止 → 暫態清空、`status` 回退 |
| Provider 錯誤 | Toast「生成失敗」+ 重試；`status` 回退 |
| Schema 驗證失敗 | AI SDK 自動重試 1 次；仍失敗則 throw |
| 前端斷線 | Partial UI 保留、DB 不寫。重按按鈕重跑 |

**Status 回退**：route handler 開頭推進（`outlining`、`drafting`）；`finally` 未走到成功分支就回退到前一狀態。

**並發保護**：
- 前端：`isGenerating` 禁用按鈕
- 後端：route handler 檢查 `articles.status`，若已在 `outlining` / `drafting` 回 409 Conflict

## 7. 編輯器與圖片

### 7.1 Tiptap 設定

**Extensions**：StarterKit + Image（自訂 node 帶 alt/caption） + Link + Markdown（tiptap-markdown） + Placeholder + FloatingMenu + CharacterCount

**初始化**：
- 若 `article.body_tiptap` 存在 → 直接載入
- 否則（草稿剛生成完）→ `markdownToTiptap(body_markdown)` 初始化，並立刻 save 回 `body_tiptap`

**Autosave**：
- Debounced 1s → Server Action `saveArticleBody(articleId, tiptapDoc)`
- Server 側同步寫入 `body_tiptap` 與 `body_markdown`（用 `tiptap-markdown` 在 server 序列化）
- 狀態：`draft_ready` 第一次編輯 → `editing`

### 7.2 圖片上傳流程

```
1. 使用者選檔 / 拖放
2. 前端呼叫 Server Action: getUploadUrl(articleId, fileType, kind)
     Server 驗證權限 → service role client → createSignedUploadUrl()
     Path = {tenant_id}/{article_id}/{kind}/{uuid}.{ext}
3. 前端直傳 signed URL（不經 Next function）
4. 上傳完 → Server Action saveImage(articleId, storagePath, kind)
     寫 article_images row，回傳 public URL
5. Tiptap node 插入 <img src={url} alt="" />
6. 使用者編輯 alt/caption → debounced → updateImage(imageId, {alt, caption})
```

**Feature image** 與 **內文 image** 使用同一流程，只差 `kind` 欄位與 UI 放置處。

## 8. Ghost 發布

### 8.1 連線設定

- 位於 `projects/[id]/settings`
- Form：Admin API URL、Admin API Key、連線名稱
- 提交：Server Action 驗證格式 → AES-256-GCM 加密 → 寫 `site_connections`
- 「測試連線」按鈕：呼叫 Ghost `/admin/site/`，更新 `last_tested_at` / `last_test_ok`

### 8.2 發布流程

Route Handler `POST /api/publish/ghost/route.ts`（Route Handler 而非 Server Action，因為可能 > 10 秒）：

```
1. 驗證 article 屬於當前 tenant（RLS 自動）
2. 查 publish_targets 是否已存在（→ edit 或 add）
3. 處理圖片：
   - 對 article_images 中的 storage_path，從 Supabase Storage 下載
   - ghost.images.upload() 上傳
   - 在 body_markdown 中將原 URL 替換為 Ghost CDN URL
4. ghost.posts.add / edit：
     html: markdownToHtml(bodyMarkdown),
     title, slug, excerpt,
     meta_title, meta_description, canonical_url,
     feature_image, tags, focus_keyword,
     status: published|draft|scheduled,
     published_at: scheduledFor ?? now()
5. 寫 publish_targets：
     remote_post_id, remote_url, remote_status, published_at
     （normalized_url 由 generated column 自動計算）
6. 寫 publish_logs
7. 回傳給前端
```

### 8.3 重新發布 / 取消發布

- **重新發布**：同 endpoint，`remote_post_id` 存在就走 `ghost.posts.edit()`
- **取消發布**：`ghost.posts.delete(remote_post_id)`，`publish_targets.remote_status = 'unpublished'`，row 保留

### 8.4 URL 正規化與 GSC 對接預備

- `publish_targets.remote_url` 存 Ghost API 回傳的 `post.url`（最終對外 URL）
- `normalized_url` 是 generated column，剝 query/fragment、轉小寫、去尾 `/`
- `url_history jsonb` 欄位預留；M2 做 slug 變更歷史追蹤時寫入
- M2 GSC 對接邏輯：GSC 資料的 `page_url` 經相同 `normalize_url()` → JOIN `publish_targets.normalized_url`
- Canonical URL 處理：若 `articles.canonical_url` 不為空，GSC 會歸給 canonical，M2 matching 時需 OR 匹配 `canonical_url`

## 9. i18n

### 9.1 Middleware

```
middleware.ts 做兩件事（有序）：
  1. @supabase/ssr updateSession() 刷新 cookie
  2. next-intl middleware 偵測 locale（cookie > Accept-Language > zh-TW）
     無 locale prefix 的路徑 → 301 到 /{detected}/...
```

### 9.2 支援 locales

- `zh-TW`（主要）
- `en`

### 9.3 UI locale vs Content locale

- UI locale：介面語言，路由 prefix（`/zh-TW/` 或 `/en/`）
- Content locale：`projects.content_locale`，AI 生成內容的語言。兩者獨立：使用者可以英文介面、中文產文。

### 9.4 訊息檔

命名空間切分 JSON（避免單一巨型檔）：`common`、`auth`、`projects`、`planning`、`articles`、`editor`、`publish`。next-intl 合併載入。

## 14. 設計過程記錄

來自 2026-04-18 brainstorm session 的關鍵決策：

1. **分階段**：Phase 1 MVP 拆成 M1（核心閉環）/ M2（數據回饋）/ M3（優化）/ M4（輔助）
2. **Tech stack 收斂**：最初提 Neon + Clerk + Drizzle，經討論改為 Supabase 全包，並移除 Drizzle（PostgREST + RLS 更自然）
3. **Tenant 表**：即使 M1 單人也保留，避免未來 FK 大遷移
4. **Article 內容雙欄位**：`body_tiptap` + `body_markdown` 並存，以免反覆轉換
5. **Phase 2 平台欄位**：用單一 `platform_meta jsonb` 而非 8 個空 column
6. **URL 正規化**：統一剝尾 `/`、小寫、無 query/fragment，兩側（storage + GSC）共用 `normalize_url()`
7. **Interview UX**：單頁清單非 wizard，使用者要能全局看題目與段落對應
8. **草稿生成 UX**：串流時顯示 plain markdown，完成後才轉入編輯器（不串流進 Tiptap，複雜度高）
9. **並發保護**：透過 `articles.status` state machine + 409 Conflict，不上 queue
10. **AI Gateway**：走 Vercel-managed + OIDC，零加價、每月 $5 免費額度
